# ADR：以稳定模块接口推进架构减法

日期 2026-11-03。按模块分阶段实施。

## 目标与基线

降低个人阅读、学习和维护成本，让常见修改集中在一个模块内部。衡量收益看调用者需要理解的概念、生产分支和修改传播范围，不用文件数量代替设计质量。


## 决策

1. **每个业务模块一页说明。** 写清职责、真实入口、调用方向、固定输入输出、失败、副作用和验证；以业务能力组织，跨 Java/Python/前端的同一能力放在同一页导航。
2. **在模块边界定义固定接口。** 接口包含已有函数、DTO、HTTP/SSE 契约，以及身份、顺序、超时和取消约束。调用方不依赖内部适配细节；不为凑层次新建转发类或接口。
3. **重构前先固定输入输出。** 定位调用者，记录成功、空结果、依赖失败、超时、取消及写入规则；挑选相关已有测试或补充接口特征用例，先在旧实现运行，再替换实现并重跑同一组用例。
4. **契约变更显式登记。** 修正规范偏差或缩减能力时，列出旧行为、目标行为、影响调用者及新增用例。不能为了让替换通过而偷偷修改预期，也不把已知缺陷永远冻结为目标行为。
5. **优先委托通用机制。** 成熟库承担协议和调度等机制；业务授权、一致性、证据准入、向量空间、预算/取消和用户数据生命周期由项目明确维护。依赖是否值得引入，要比较可删除的实现与新增的配置、依赖和运维成本。
6. **按一个模块完成闭环。** 说明与契约 → 旧实现特征验证 → 内部替换 → 针对性验证 → 登记相对原有接口的变化。未触及模块不补跑历史全套。

## 执行顺序与范围

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| S0 | 支持范围与模块契约清单 | 区分当前承诺、可收缩候选、未验证事实；每个模块有一页入口说明 |
| S1 | SSE 帧解析替换 | 既有输入输出先通过；共用成熟解析器；请求、鉴权、取消和终止语义有针对性证据 |
| S2 | 模型协议与 Agent 兼容层收缩 | 先列实际模型能力矩阵和调用契约，再决定移除哪些协议/正文工具恢复；不改用户绑定或隐式迁移向量 |
| S3 | 默认观测部署减负 | 核对消费者与导出链，减少默认常驻服务；保留必要指标、请求关联和产品 Trace |
| S4 | 任务职责与内部接口整理 | 事务、锁顺序、投递、重试、恢复和提交后通知规则不丢失 |

S0 先固定当时的对外行为。S2 选择的模型协议如下。Chat/Embedding 收缩为 OpenAI 兼容协议，Agent 仅保留原生工具调用，Rerank 保留两协议；不自动迁移旧模型或索引。详情见 [能力矩阵](contracts/model-agent-capability-matrix.md)。双 RAG 引擎取舍、解析器统一、对象回收和 mock 删除不进入当前首轮。

## 验证与进度

通过[模块导航](modules/README.md)找到边界两侧的源码。核对实际调用者、生产类型、模块 README 和相关测试，再更新受影响的公开约定。

每项分别记录单元/契约测试、静态检查、构建、浏览器及真实依赖结果。没有执行就写未执行，旧证据不自动覆盖改变的契约。保留已有失败、验收待办、运行数据、用户改动，不自动提交、推送或部署。

## 开发版本策略修订（2026-11-03）

当前是开发版本。旧账号、旧模型和旧索引不构成默认向后兼容或数据迁移义务。此前“先迁移旧模型/索引才能使用新版本”的排期取消；默认用当前支持的配置、新账号/新知识库验证新版本。只有明确需要复用数据或对比当前行为时，才保留对应旧夹具或安排迁移，不为假定的旧用户增加兼容层。

验证以本次修改的当前契约为准：确定性缺陷保留小范围修复前失败/修复后通过的用例；其余模块按实际改动和当前契约选取检查。

当前版本仍保持授权、凭证隔离、向量空间/维度绑定、短事务和 Flyway 追加迁移等约束。索引重建仍服务于当前版本的模型/维度切换；“无需迁移旧配置”不意味着可以混用向量空间或自动清空现有数据库。真正清空、删除或切换数据源时须先明确操作目标与保留需求。

## S5 决策补充（2026-11-03）

运行 Store 只保留 Redis，必要的内存替身归入测试源码；确认采用 Resilience4j 的标准计数失败率规则（窗口 10、最小 5、阈值 50%、冷却 10 秒、半开 1 次），替代原成功清零的手写计数。连接故障和 5xx 计入，读超时/取消排除。
